# Spike findings — 2026-11-06

Claude Code 2.1.319, Linux. Probe plugin loaded with `claude --plugin-dir`, two interactive sessions started in tmux **with a clean environment** (`env -i`, so nothing was inherited from the session that launched them) in the same working directory. Probe code is not kept; ids below are shortened.

## 1. Session scoping — decision (a)

- The monitor process environment carries `CLAUDE_CODE_SESSION_ID` (session A `b51f…`, session B `a231…`, different per session) and `CLAUDE_PID` (the session's Claude Code process).
- The `PostToolUse` hook stdin `session_id` of session A was `b51f…`, equal to the hook's own `CLAUDE_CODE_SESSION_ID` env and to session A's monitor `CLAUDE_CODE_SESSION_ID`.
- Hook and monitor of the same session share `CLAUDE_PID`; the two sessions differ.
- `${CLAUDE_PLUGIN_DATA}` substitutes in the monitor command (it arrived as `--data /home/<user>/.claude/plugins/data/<plugin-id>`). With `--plugin-dir` the id is `<name>-inline`; the hook receives the same path as `CLAUDE_PLUGIN_DATA` env.
- Process tree: `claude` → `zsh -c …` (user shell snapshot) → `node probe.mjs`. So the monitor's direct parent is a shell, not Claude; `CLAUDE_PID` is the reliable parent to watch.

**Decision: (a).** Spool keyed by session id. Hook: `input.session_id`. Watcher: `process.env.CLAUDE_CODE_SESSION_ID`. If that variable is missing (other host/version), the watcher reports one error line and polls nothing — never falls back to a shared spool.

## 2. Monitor output wakes an idle session — yes

- Session B idle at the prompt: the probe's stdout line arrived as `● Monitor event: <line> · <description>` and started a turn by itself.
- Line emitted while a turn was running (a 150 s foreground command): it was delivered into that running turn, not lost.

## 4. Lifetime and resume

- `/exit`: the session's monitor process was gone within a second.
- `claude --resume <session id>`: a new monitor process started with **the same** `CLAUDE_CODE_SESSION_ID` and a new `CLAUDE_PID`. Open watches therefore carry over to a resumed session.
- Consequence for the watcher's parent-gone check: use `CLAUDE_PID` (alive check), not `process.ppid`.
